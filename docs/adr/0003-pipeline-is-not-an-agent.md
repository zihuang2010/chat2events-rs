# ADR-0003：①~⑦ 这条线不做成 agent

- 状态：**已采纳**
- 相关：全线

## 决策

不把 ①~⑦ 做成 agent。**任何「加 agent」的提案，先回答它把「模型决定什么」那张表的哪一格
从右边挪到了左边。** 挪不动格子的才是好提案。

⚠️ 注意本项目的 `agent` 一词指**平台客服**（`INTERNAL`），不是 LLM agent。见 `CONTEXT.md` 术语表。

## agent 的两个真位置（都在这条线之外）

- **A** `taxonomy` 归纳进程——人工触发、只产词表、不写 `event` 表、失败无所谓。
- **B** 抽检 / LLM-as-judge——读录下来的段 + 抽出的事件，标出可疑的。补的正是
  「事件数不变不等于事件对」这个盲区。

## 原文

- **不把 ①~⑦ 这条线做成 agent。** 判据写在这里，省得反复讨论：**任何「加 agent」的提案，先回答它把「模型决定什么」那张表的哪一格从右边挪到了左边。** 挪不动格子的才是好提案。

  | 阶段 | 模型决定 | 代码决定 |
  |---|---|---|
  | ① 摄取 / ② 会话 | 什么都不 | 字段映射 · 版本断言 · 分组 · 排序 · 计数 |
  | ③ 抽取 | **哪些行号是同一件事 · summary · 接哪条便签 · 完没完** | 分段 · 切点 · 便签内容 · 脱敏 · 行号↔`msg_id` 映射 |
  | ④ 装配 | 什么都不 | 11 个事实字段全部从真实消息算出 |
  | ⑤ 分类 | （v1 才上场，且被缓存钉死） | 确定性 · 缓存 · 版本 |

  四条具体理由：**(1)** 这是归组任务不是推理任务 —— 关掉 reasoning 实测 251s → 31s 而事件 45 → 47（没变少）；**(2)** 长程记忆（最长事件跨 951 行）便签已经接住了，agent 是为已解决的问题付第二次钱；**(3)** 成本 —— 一次调用变成 5~10 次且上下文累积，`ROOM_CONCURRENCY` 的 TPM 推导直接作废；**(4)** **可审计** —— 主管点开「首响 3 分钟」要看到是哪几条消息，而下钻能成立正是因为 `source_msg_ids` 是代码算的、模型碰不到；给 agent 一个 `query_messages` 工具，「模型编造 msgid」这个失败模式立刻回来。

  **agent 有两个真位置，都在这条线之外**：**A** `taxonomy` 归纳进程（人工触发、只产词表、不写 `event` 表、失败无所谓）；**B** 抽检 / LLM-as-judge（读录下来的段 + 抽出的事件，标出可疑的 —— 补的正是「事件数不变不等于事件对」这个盲区）。
